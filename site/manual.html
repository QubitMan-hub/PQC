Guide · TLS 1.3 + mTLS

From nothing to a protected service, step by step.

Each step is one or two commands, with what you should see. It takes about fifteen minutes. Everything runs on your own computer.

Four words first

What the commands talk about

TLS
The lock on a connection. The server proves who it is, and everything sent is encrypted.
Mutual TLS (mTLS)
Both sides prove who they are: the client shows a certificate too.
Certificate authority (CA)
Your own issuer of certificates, the ID cards that servers and clients show.
CRL
The CA's signed list of cancelled (revoked) certificates. Servers check it on every connection.

Before you start

Install

You need Python 3.11 or newer and OpenSSL 3.5 or newer. Python has it built in only on recent Linux, so most computers need one extra step:

Your computerGet OpenSSL 3.5
WindowsInstall the 64-bit OpenSSL 3.5 (or newer) build for Windows. Then, in PowerShell: $env:PQC_OPENSSL = "C:\Program Files\OpenSSL-Win64\bin" (the folder that holds libssl-3-x64.dll).
macOSbrew install openssl@3, then export PQC_OPENSSL="$(brew --prefix openssl@3)/lib"
Debian 13, Ubuntu 25.04+Nothing to do: it is the system OpenSSL.
Anything with DockerSkip all of this: docker build -t pqc https://github.com/QubitMan-hub/PQC.git#main, then docker run --rm pqc runs the tour.

Then get the code and install it:

git clone https://github.com/QubitMan-hub/PQC
cd PQC
pip install .
pqc doctor

You should see TLS edge: ready. If it says OpenSSL was not found or is too old, the message names the next step; fix that before going on.

Step by step

Protect a connection

Work in an empty folder. Some steps need a second terminal: open it in the same folder.

  1. Watch the one-minute tour

    pqc try

    You should see a page fetched with X25519MLKEM768 and ML-DSA-65, and a classical-only client refused, as it should be. It cleans up after itself.

  2. Create your certificate authority

    pqc ca init --name "My Test Root"

    It asks for a passphrase twice: this protects the CA's key, so remember it. Everything goes in a folder called pki.

    You should see created ML-DSA-87 root 'My Test Root' in pki

  3. Give a server its certificate

    pqc ca issue server localhost --san 127.0.0.1 --out server

    You should see issued server certificate … for localhost (ML-DSA-65) and three files in server.

  4. Test a protected connection

    In the first terminal, start a test server that repeats back whatever it receives. Leave it running:

    pqc tls serve --listen 127.0.0.1:8443 --cert server/chain.pem --key server/key.pem

    In the second terminal, connect to it:

    pqc tls connect localhost:8443 --ca pki/ca.crt --send hello

    You should see group X25519MLKEM768 (the post-quantum key exchange), peer_key ML-DSA-65 (the post-quantum certificate) and reply hello. Stop the server with Ctrl+C.

  5. Let in only clients with a certificate (mutual TLS)

    Issue a certificate for a client called alice:

    pqc ca issue client alice --out alice

    In the first terminal, start the test server again, now asking every client for a certificate from your CA and checking the revocation list:

    pqc tls serve --listen 127.0.0.1:8443 --cert server/chain.pem --key server/key.pem --ca pki/ca.crt --require-client-cert --crl pki/crl.pem

    In the second terminal, connect without a certificate, then as alice:

    pqc tls connect localhost:8443 --ca pki/ca.crt --send hello
pqc tls connect localhost:8443 --ca pki/ca.crt --cert alice/chain.pem --key alice/key.pem --send hello

    You should see the first one refused (it refused our client certificate) and alice get reply hello.

  6. Cut a client off: revoke

    Alice's laptop is stolen. Find her certificate's serial number (the first column), then revoke it:

    pqc ca list
pqc ca revoke SERIAL --reason keyCompromise

    Connect as alice again, with the same command as before:

    pqc tls connect localhost:8443 --ca pki/ca.crt --cert alice/chain.pem --key alice/key.pem --send hello

    You should see alice refused. The server's terminal says certificate … was revoked. Nobody restarted the server. Stop it with Ctrl+C.

  7. Put your own application behind it

    Start your application on port 8080. To try with a stand-in, Python's built-in web server will do:

    python -m http.server 8080 --bind 127.0.0.1

    In another terminal, put the edge in front of it. The application does not change:

    pqc tls edge --listen 127.0.0.1:8443 --target 127.0.0.1:8080 --cert server/chain.pem --key server/key.pem

    Check the protection:

    pqc tls connect localhost:8443 --ca pki/ca.crt

    You should see X25519MLKEM768 and ML-DSA-65. Your application's own clients connect to port 8443 and trust pki/ca.crt. For mutual TLS, add --ca pki/ca.crt --require-client-cert --crl pki/crl.pem to the edge, as in step 5.

Prefer clicking

The console

The same steps in a browser page, on your own machine.

pqc console --edge http://127.0.0.1:9100

You should see console on http://localhost:8900/ and your browser opening it. If it asks for a token, paste the one the command printed. --edge is the --metrics address of an edge; leave it out if you have none yet. The CA's folder is pki unless you give --ca.

EdgesLive connections, handshakes and key-exchange groups for each edge, every 5 seconds.

Client setupReady-to-copy settings for the pqc command, curl, Python, nginx, and any other app (Java included) through a local edge.

Every action is written to console-audit.jsonl. To reach the console from another machine, put pqc tls edge --policy transition in front of it rather than listening beyond localhost.

Choices

Which policy

Set it with --policy on the edge.

PolicyWho gets inUse it for
strict (default)Only post-quantum clientsAPIs, databases, partners, anything you control both ends of
transitionAlso classical clients; add --fallback-cert and --fallback-key (an ECDSA or RSA certificate) for browsersWebsites, while browsers cannot check ML-DSA yet
cnsa2Only ML-KEM-1024, ML-DSA-87 and AES-256The stronger profile CNSA 2.0 asks for

Keep it running

After the first day

  • Once a day: pqc ca maintain renews certificates that expire within 30 days and re-signs the revocation list. An expired list refuses everyone, on purpose. Schedule it with Task Scheduler on Windows or cron elsewhere.
  • Several routes, one file: examples/edge.toml shows every setting; run it with pqc tls edge --config edge.toml. Changes load without a restart.
  • CA on another machine: pqc ca publish serves the revocation list, and crl_url in the edge's file fetches it every minute.
  • Before going live: pqc doctor --ca pki --config edge.toml checks key protection, revocation list freshness, expiring certificates and risky settings.

If something goes wrong

Troubleshooting

What you seeWhat to do
pqc is not foundUse the same terminal and Python you installed with, or run python -m pqc instead.
OpenSSL 3.5+ was not found, or is too oldInstall it as in Install, set PQC_OPENSSL, and run pqc doctor again.
connection refusedNothing is listening on that port: start the server or edge first, and check the port number.
it refused our client certificateMutual TLS is on: give --cert and --key, and check the certificate is not revoked (pqc ca list).
The name does not match the certificateConnect with the name the certificate was issued for, or add --server-name NAME.
Everyone is refused after a weekThe revocation list expired: run pqc ca maintain, and schedule it daily.

Never switch off certificate checks to make a connection work: fix the CA, the name, the clock or the policy instead.
